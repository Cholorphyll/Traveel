MODULE — ACTION HORIZON ENGINE — SQL / TABLE / COMPUTATION SPEC
Purpose
The Action Horizon Engine determines when an entity matters to the traveler.
It separates candidates into 3 temporal horizons:
* DO NOW → best for immediate action
* DO SOON → highly relevant soon, but not necessarily this second
* TRIP IMPORTANT → important to know / not miss during the trip
This module should not replace structural or opportunity scoring.
It should work as a time-horizon layer on top of them.
________________


FINAL ARCHITECTURE
You should implement this in 2 layers:
Layer A — Static / Semi-static Priors (batch computed)
These are stable or slow-changing entity-level traits.
Stored in:
* entity_action_horizon_priors
Layer B — Runtime Horizon Scoring (session/context computed)
These depend on:
* current time
* weather
* route
* user position
* trip stage
* current context
Stored in:
* session_entity_action_horizon_scores
________________

PART 3 — NORMALIZATION RULES
Every score must be normalized to:
0.0000 → 1.0000


Standard normalization rule:
normalized_score = clamp(raw_value, 0, 1)


Level conversion rule (0–5 to 0–1):
normalized_score = level / 5.0


Reverse density rule:
For fields like substitution density:
trip_uniqueness_score = 1 - (substitution_density_level / 5.0)

4.1 Populate trip_anchor_importance_score
Source
This should come from your Structural Importance Engine.
Assuming you already have:
* entity_structural_scores.structural_importance_score
SQL
INSERT INTO entity_action_horizon_priors (
    entity_type,
    entity_id,
    trip_anchor_importance_score
)
SELECT
    entity_type,
    entity_id,
    structural_importance_score
FROM entity_structural_scores
ON DUPLICATE KEY UPDATE
    trip_anchor_importance_score = VALUES(trip_anchor_importance_score),
    updated_at = NOW();


________________


4.2 Populate trip_regret_risk_score
This should represent:
“How likely is the traveler to regret missing this?”
Recommended formula
trip_regret_risk_score =
0.40 * landmark_score
+ 0.30 * iconic_score
+ 0.30 * popularity_score


If you don’t have all 3, use your available proxies.
Assumed source columns
From your entity master / aggregated entity table:
* landmark_level
* popularity_score
* iconic_score
SQL
INSERT INTO entity_action_horizon_priors (
    entity_type,
    entity_id,
    trip_regret_risk_score
)
SELECT
    em.entity_type,
    em.entity_id,
    LEAST(
        1.0,
        (0.40 * COALESCE(em.landmark_score, 0)) +
        (0.30 * COALESCE(em.iconic_score, 0)) +
        (0.30 * COALESCE(em.popularity_score, 0))
    ) AS trip_regret_risk_score
FROM entity_master em
ON DUPLICATE KEY UPDATE
    trip_regret_risk_score = VALUES(trip_regret_risk_score),
    updated_at = NOW();


________________


4.3 Populate trip_uniqueness_score
Logic
trip_uniqueness_score = 1 - substitution_density_score


If using 0–5 density level:
trip_uniqueness_score = 1 - (substitution_density_level / 5.0)


SQL
INSERT INTO entity_action_horizon_priors (
    entity_type,
    entity_id,
    trip_uniqueness_score
)
SELECT
    entity_type,
    entity_id,
    ROUND(1 - (COALESCE(substitution_density_level, 5) / 5.0), 4) AS trip_uniqueness_score
FROM entity_horizon_metadata
ON DUPLICATE KEY UPDATE
    trip_uniqueness_score = VALUES(trip_uniqueness_score),
    updated_at = NOW();

+ 0.30 * schedule_dependency_score
+ 0.20 * transit_dependency_score
+ 0.15 * coordination_need_score

0.45 * reservation_need_level_norm
+ 0.35 * schedule_dependency_level_norm
+ 0.20 * transit_dependency_level_norm

4.9 Populate effort_level_score
Important
This should be reversed so that:
* low effort = high score
* high effort = low score
Formula
effort_level_score = 1 - ((effort_level - 1) / 4.0)


Examples:
effort_level
	effort_level_score
	1
	1.00
	2
	0.75
	3
	0.50
	4
	0.25
	5
	0.00
	SQL
INSERT INTO entity_action_horizon_priors (
    entity_type,
    entity_id,
    effort_level_score
)
SELECT
    entity_type,
    entity_id,
    ROUND(
        CASE
            WHEN effort_level IS NULL THEN 0.50
            ELSE 1 - ((effort_level - 1) / 4.0)
        END,
        4
    )
FROM entity_horizon_metadata
ON DUPLICATE KEY UPDATE
    effort_level_score = VALUES(effort_level_score),
    updated_at = NOW();

PART 6 — RUNTIME FEATURE CALCULATION
Now let’s define the exact formulas for each runtime field.
________________


6.1 open_now_score
Formula
if is_open_now = 1 → 1.00
else if minutes_to_open <= 30 → 0.80
else if minutes_to_open <= 120 → 0.55
else if opens later today → 0.30
else → 0.15


SQL pattern
CASE
    WHEN is_open_now = 1 THEN 1.00
    WHEN minutes_to_open BETWEEN 0 AND 30 THEN 0.80
    WHEN minutes_to_open BETWEEN 31 AND 120 THEN 0.55
    WHEN minutes_to_open > 120 THEN 0.30
    ELSE 0.15
END


________________


6.2 immediate_time_fit_score
Logic
Pull current daypart score from entity_time_affinity.
Example SQL
If current daypart = sunset:
SELECT
    COALESCE(sunset_score, 0.50) AS immediate_time_fit_score
FROM entity_time_affinity
WHERE entity_type = :entity_type
  AND entity_id = :entity_id;


Fallback default:
0.50


________________


6.3 immediate_weather_fit_score
Logic
Pull current weather affinity.
If weather = rainy:
SELECT
    COALESCE(rainy_score, 0.50) AS immediate_weather_fit_score
FROM entity_weather_affinity
WHERE entity_type = :entity_type
  AND entity_id = :entity_id;


Fallback default:
0.50


________________


6.4 immediate_queue_risk_score
Logic
Use expected queue / crowd estimate if available.
If not, default to:
0.65


Formula
<=10 min queue → 1.00
<=25 min → 0.75
<=45 min → 0.50
<=90 min → 0.25
>90 min → 0.10


________________


6.5 immediate_accessibility_score
Formula
immediate_accessibility_score =
0.40 * transport_access_score
+ 0.30 * entry_ease_score
+ 0.30 * route_feasibility_score


If you do not yet have those sub-components, use this simplified proxy:
immediate_accessibility_score =
0.60 * immediate_distance_fit_score
+ 0.40 * open_now_score


Recommended simplified runtime formula
immediate_accessibility_score =
(0.60 * immediate_distance_fit_score)
+ (0.40 * open_now_score)


________________


6.6 immediate_energy_fit_score
Inputs
* energy_state
* effort_level_score
Formula
If energy_state = low
immediate_energy_fit_score = effort_level_score


If energy_state = medium
immediate_energy_fit_score = 0.80 + (0.20 * effort_level_score)


If energy_state = high
immediate_energy_fit_score = 0.60 + (0.40 * (1 - ABS(0.50 - effort_level_score)))


Simpler production-safe version
low energy   → use effort_level_score directly
medium energy → clamp(0.70 + 0.30 * effort_level_score)
high energy  → 0.75 fixed default unless later modeled better


Recommended first implementation
if ($energyState === 'low') {
    $immediateEnergyFitScore = $effortLevelScore;
} elseif ($energyState === 'medium') {
    $immediateEnergyFitScore = min(1, 0.70 + (0.30 * $effortLevelScore));
} else {
    $immediateEnergyFitScore = 0.75;
}

<= 400m   → 1.00
<= 1000m  → 0.85
<= 2500m  → 0.60
<= 5000m  → 0.35
> 5000m   → 0.15

6.8 immediate_booking_urgency_score
Formula
immediate_booking_urgency_score =
0.70 * base_booking_urgency_score
+ 0.30 * time_proximity_pressure


Example time_proximity_pressure
if deadline within 3h → 1.00
within 12h → 0.80
within 24h → 0.60
within 48h → 0.35
else → 0.15


If you don’t yet have real deadlines, use:
immediate_booking_urgency_score = base_booking_urgency_score


That is a good V1.

PART 7 — DO SOON FEATURE CALCULATION
________________


7.1 upcoming_time_window_score
Formula
upcoming_time_window_score =
base_time_window_strength_score × temporal_proximity_factor


temporal_proximity_factor
ideal window starts in <= 1h  → 1.00
<= 3h → 0.80
<= 6h → 0.55
tomorrow → 0.30
later → 0.10


If no future window exists:
0.20


________________


7.2 upcoming_booking_deadline_score
Formula
within 3h  → 1.00
within 12h → 0.85
within 24h → 0.70
within 48h → 0.45
else → 0.15


If you don’t yet have explicit deadline data:
upcoming_booking_deadline_score = base_booking_urgency_score


That is acceptable for V1.
________________


7.3 upcoming_weather_opportunity_score
Formula
upcoming_weather_opportunity_score =
future_weather_fit_score × future_weather_proximity_factor


Example
If sunset clear-sky window is 2 hours away:
* future_weather_fit_score = 0.95
* future_weather_proximity_factor = 0.80
Then:
0.76


If you do not yet have forecast window modeling:
upcoming_weather_opportunity_score = immediate_weather_fit_score


This is acceptable for V1.
________________

7.6 upcoming_trip_stage_fit_score
Formula
Use rule-based scoring.
________________


If trip_stage = arrival
Entity Pattern
	Score
	nearby / low-effort / orientation
	0.90
	dinner / essentials / easy walk
	0.85
	hard logistics / far detour
	0.35
	________________


If trip_stage = mid_trip
Entity Pattern
	Score
	major anchors
	0.90
	route-compatible clusters
	0.85
	filler
	0.50
	________________


If trip_stage = departure
Entity Pattern
	Score
	short, meaningful, easy
	0.90
	airport-compatible
	0.85
	full-day heavy item
	0.20
	First implementation recommendation
Use a simplified heuristic:
arrival:
    low effort + nearby = high


mid_trip:
    structural importance + route fit = high


departure:
    low effort + high regret = high


Suggested formula
upcoming_trip_stage_fit_score =
CASE trip_stage
  arrival   → 0.60 * effort_level_score + 0.40 * immediate_distance_fit_score
  mid_trip  → 0.60 * trip_anchor_importance_score + 0.40 * upcoming_route_fit_score
  departure → 0.50 * effort_level_score + 0.50 * trip_regret_risk_score
END

PART 8 — FINAL HORIZON FORMULAS
Now we compute the final outputs.
________________


8.1 DO NOW
Base formula
do_now_score =
(
  0.18 * open_now_score
+ 0.15 * immediate_time_fit_score

do_now_gating_factor
Formula
do_now_gating_factor =
availability_gate × degradation_gate × hard_block_gate


availability_gate
availability_gate = max(0.15, open_now_score)


degradation_gate
degradation_gate =
1
- (0.35 * weather_block_flag)
- (0.35 * access_block_flag)
- (0.30 * safety_flag)


Clamp to:
0.0 → 1.0


hard_block_gate
if permanently_closed OR impossible_now = 1 → 0
else → 1
