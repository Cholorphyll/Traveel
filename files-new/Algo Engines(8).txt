MODULE — ROLE ASSIGNMENT ENGINE
Full SQL / Table / Computation Spec
________________


6.0 Purpose
The Role Assignment Engine determines:
“What function should this item play in the feed right now?”
It converts upstream scores into feed jobs.
This is the module that decides whether an item is acting as:
* a main destination
* a next move
* a recovery stop
* a meal fit
* a windowed opportunity
* a scenic moment
* a planning save
* etc.
This is not a ranking module.
It is a semantic role layer that later helps the feed ranking module produce a more human-feeling sequence.
________________


6.1 Output Contract
For each candidate item in the active feed context, the engine should output:
Required fields
* assigned_roles
* role_confidence
Strongly recommended production fields
* primary_role
* secondary_roles
* role_group
* role_reason_codes
* primary_role_score
* second_best_role_score
* role_priority
* role_selection_score

6.3 System Architecture (Recommended)
Use 3 tables + 1 view.
________________


Tables / View
1. Input feature view
vw_role_assignment_inputs


2. Per-role scoring table
trip_item_role_scores


3. Final resolved role table
trip_item_roles


4. Optional config table
role_threshold_config


This structure is much better than a single giant unreadable query.

6.5 Required Derived Inputs (Important)
Some inputs should be derived before role scoring.
You should calculate these once in your staging pipeline.
________________


6.5.1 immediate_accessibility_score
CASE
    WHEN opening_status_now = 1 AND travel_time_minutes <= 20 THEN 1.00
    WHEN opening_status_now = 1 AND travel_time_minutes <= 35 THEN 0.75
    WHEN opening_status_now = 1 AND travel_time_minutes <= 50 THEN 0.45
    ELSE 0.10
END


________________


6.5.2 accessibility_score
CASE
    WHEN travel_time_minutes <= 25 THEN 1.00
    WHEN travel_time_minutes <= 40 THEN 0.70
    WHEN travel_time_minutes <= 60 THEN 0.35
    ELSE 0.10
END


________________


6.5.3 low_detour_score
CASE
    WHEN detour_cost_minutes <= 5 THEN 1.00
    WHEN detour_cost_minutes <= 10 THEN 0.75
    WHEN detour_cost_minutes <= 15 THEN 0.45
    ELSE 0.10
END


________________


6.5.4 short_dwell_fit
CASE
    WHEN avg_dwell_minutes <= 20 THEN 1.00
    WHEN avg_dwell_minutes <= 40 THEN 0.70
    WHEN avg_dwell_minutes <= 60 THEN 0.40
    ELSE 0.10
END


________________


6.5.5 low_friction_score
LEAST(
    1.0,
    (
        0.40 * low_effort_access_score +
        0.30 * open_now_score +
        0.30 * (1 - LEAST(detour_cost_minutes / 20.0, 1.0))
    )
)


________________


6.5.6 low_commitment_score
CASE
    WHEN avg_dwell_minutes <= 30 AND is_high_commitment = 0 THEN 1.00
    WHEN avg_dwell_minutes <= 60 THEN 0.70
    WHEN avg_dwell_minutes <= 90 THEN 0.40
    ELSE 0.15
END


________________


6.5.7 signal_coverage_score
This is for confidence later.
(
    (CASE WHEN structural_importance_score IS NOT NULL THEN 1 ELSE 0 END) +
    (CASE WHEN context_relevance_score IS NOT NULL THEN 1 ELSE 0 END) +
    (CASE WHEN opportunity_score IS NOT NULL THEN 1 ELSE 0 END) +
    (CASE WHEN do_now_score IS NOT NULL THEN 1 ELSE 0 END) +
    (CASE WHEN do_soon_score IS NOT NULL THEN 1 ELSE 0 END)
) / 5.0

6.9 Computation Strategy
For every candidate item:
Step 1
Compute a score for every role
Step 2
Mark roles as eligible if:
role_score >= min_role_score


Step 3
Compute:
role_selection_score = 0.80 * role_score + 0.20 * role_priority_weight


Step 4
Pick the highest role_selection_score among eligible roles as primary_role
Step 5
All other eligible roles become secondary_roles

6.10.1 CURRENT_ANCHOR
INSERT INTO trip_item_role_scores (
    session_id, trip_id, user_id, candidate_item_id,
    role_name, role_group, role_score, eligible_flag,
    role_priority_weight, role_selection_score, reason_codes_json

SELECT
    v.session_id,
    v.trip_id,
    v.user_id,
    v.candidate_item_id,


    'CURRENT_ANCHOR',
    'structural',


    (
        0.30 * v.structural_importance_score +
        0.25 * v.context_relevance_score +
        0.20 * v.do_now_score +
        0.15 * v.anchor_score +
        0.10 *
        CASE
            WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 20 THEN 1.00
            WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 35 THEN 0.75
            WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 50 THEN 0.45
            ELSE 0.10
        END
    ) AS role_score,


    CASE
        WHEN (
            0.30 * v.structural_importance_score +
            0.25 * v.context_relevance_score +
            0.20 * v.do_now_score +
            0.15 * v.anchor_score +
            0.10 *
            CASE
                WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 20 THEN 1.00
                WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 35 THEN 0.75
                WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 50 THEN 0.45
                ELSE 0.10
            END
        ) >= 0.72 THEN 1 ELSE 0
    END,


    0.97,


    (
        0.80 * (
            0.30 * v.structural_importance_score +
            0.25 * v.context_relevance_score +
            0.20 * v.do_now_score +
            0.15 * v.anchor_score +
            0.10 *
            CASE
                WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 20 THEN 1.00
                WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 35 THEN 0.75
                WHEN v.opening_status_now = 1 AND v.travel_time_minutes <= 50 THEN 0.45

    JSON_ARRAY(
        CASE WHEN v.structural_importance_score >= 0.75 THEN 'high_structural_importance' END,
        CASE WHEN v.context_relevance_score >= 0.70 THEN 'high_context_fit' END,
        CASE WHEN v.do_now_score >= 0.70 THEN 'high_do_now_fit' END,

6.11 Final Role Resolution Query
Now resolve the primary and secondary roles.
________________


Step A — rank eligible roles per item
WITH ranked_roles AS (
    SELECT
        r.*,
        ROW_NUMBER() OVER (
            PARTITION BY r.session_id, r.trip_id, r.user_id, r.candidate_item_id
            ORDER BY r.role_selection_score DESC, r.role_score DESC
        ) AS rn
    FROM trip_item_role_scores r
    WHERE r.eligible_flag = 1

INSERT INTO trip_item_roles (
    session_id,
    trip_id,
    user_id,
    candidate_item_id,
    candidate_item_type,
    assigned_roles,
    primary_role,
    secondary_roles,
    role_group,
    role_confidence,
    primary_role_score,
    second_best_role_score,
    role_priority,
    role_selection_score,
    role_reason_codes
)
WITH ranked_roles AS (
    SELECT
        r.*,
        i.candidate_item_type,
        ROW_NUMBER() OVER (
            PARTITION BY r.session_id, r.trip_id, r.user_id, r.candidate_item_id
            ORDER BY r.role_selection_score DESC, r.role_score DESC
        ) AS rn
    FROM trip_item_role_scores r
    JOIN vw_role_assignment_inputs i
      ON i.session_id = r.session_id
     AND i.trip_id = r.trip_id
     AND i.user_id = r.user_id
     AND i.candidate_item_id = r.candidate_item_id
    WHERE r.eligible_flag = 1
),
role_summary AS (
    SELECT
        session_id,
        trip_id,
        user_id,
        candidate_item_id,
        MAX(candidate_item_type) AS candidate_item_type,


        JSON_ARRAYAGG(role_name) AS assigned_roles,


        MAX(CASE WHEN rn = 1 THEN role_name END) AS primary_role,
        JSON_ARRAYAGG(CASE WHEN rn > 1 THEN role_name END) AS secondary_roles,
        MAX(CASE WHEN rn = 1 THEN role_group END) AS role_group,


        MAX(CASE WHEN rn = 1 THEN role_score END) AS primary_role_score,
        MAX(CASE WHEN rn = 2 THEN role_score END) AS second_best_role_score,
        MAX(CASE WHEN rn = 1 THEN role_priority_weight END) AS role_priority,
        MAX(CASE WHEN rn = 1 THEN role_selection_score END) AS role_selection_score,
        MAX(CASE WHEN rn = 1 THEN reason_codes_json END) AS role_reason_codes


    FROM ranked_roles
    GROUP BY session_id, trip_id, user_id, candidate_item_id
)
SELECT
    session_id,
    trip_id,
    user_id,
    candidate_item_id,
    candidate_item_type,
    assigned_roles,
    primary_role,
    secondary_roles,
    role_group,


    LEAST(
        1.0,
        (
            0.50 * primary_role_score +
            0.20 * GREATEST(0, primary_role_score - COALESCE(second_best_role_score, 0)) +
            0.15 * 0.85 +
            0.15 * 0.85
        )
    ) AS role_confidence,


    primary_role_score,
    second_best_role_score,
    role_priority,
    role_selection_score,
    role_reason_codes


FROM role_summary;

6.12 Better role_confidence Formula (Recommended)
The query above uses placeholders for the last two terms.
For production, use:
role_confidence =
0.50 * normalized_primary_role_score
+ 0.20 * score_gap_vs_second_best
+ 0.15 * signal_coverage_score
+ 0.15 * context_alignment_stability

Suggested SQL Version
LEAST(
    1.0,
    (
        0.50 * primary_role_score +
        0.20 * GREATEST(0, primary_role_score - COALESCE(second_best_role_score, 0)) +
        0.15 * signal_coverage_score +
        0.15 * context_alignment_stability
    )

Where:
signal_coverage_score
Can be precomputed in your input view.
context_alignment_stability
Can be approximated as:
CASE

    WHEN primary_role IN ('DINNER_DESTINATION','LUNCH_FIT_ITEM','MEAL_WINDOW_ITEM') THEN 0.80
    WHEN primary_role IN ('CURRENT_ANCHOR','NEXT_ANCHOR') THEN 0.85
    ELSE 0.75

6.13 Strongly Recommended Conflict Rules
This is important.
Some roles should suppress or downgrade others.
Without this, your output will be noisy.
________________


Rule 1 — DINNER_DESTINATION suppresses MEAL_WINDOW_ITEM
If both eligible:
* keep both in assigned_roles
* but DINNER_DESTINATION should usually win as primary
This is already handled via higher role_priority_weight.
________________


Rule 2 — WINDOWED_EXPERIENCE can override CURRENT_ANCHOR
If:
window_strength_score >= 0.80
AND time_sensitivity_score >= 0.75
AND reachability_before_window_end >= 0.65


Then WINDOWED_EXPERIENCE should win unless CURRENT_ANCHOR is extremely dominant.
________________


Rule 3 — NEXT_DAY_CANDIDATE should never be primary if strong “now” roles exist
You can enforce this by excluding it if item also has:
* CURRENT_ANCHOR
* NEXT_ANCHOR
* WINDOWED_EXPERIENCE
* MEAL_WINDOW_ITEM
* DINNER_DESTINATION
* RECOVERY_ITEM
________________


Rule 4 — UTILITY_SUPPORT should rarely be primary
Keep it available for downstream balancing, but it should almost never dominate unless user state is utility-heavy.
