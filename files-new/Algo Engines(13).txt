MODULE — MOMENT FRAMING ENGINE
Full SQL / Table / Computation / UX Specification
________________


10.0 PURPOSE
The Moment Framing Engine converts ranked feed decisions into human-readable “why now” framing.
It answers:
“Why is this showing up for me right now?”
It should explain:
* why this item fits the current moment
* why it matters in the user’s current situation
* what kind of action or mindset it supports
* how urgently or softly it should be framed
It does not decide the item itself.
That has already been decided by earlier modules:
* Base Relevance
* Opportunity Engine
* Action Horizon Engine
* Role Assignment Engine
* Route Engine
* Sequence Planner
* Slot Ranking Engine
Moment Framing takes those outputs and transforms them into:
* moment tags
* explanation reasons
* framing intensity
* CTA style
* short user-facing labels
* secondary support reasons
________________


10.1 CORE DESIGN PRINCIPLE
The system chooses.
Moments explain.
That means:
❌ Wrong architecture:
“Generate a cute reason for each recommendation.”
✅ Correct architecture:
“Use system evidence to derive the strongest explanation pattern.”
A moment must therefore be:
* true
* situational
* useful
* specific
* behaviorally aligned
* not generic fluff
________________


10.2 WHAT A “MOMENT” REALLY IS
A moment is a structured explanation layer that combines:
* user context
* environment context
* trip state
* movement state
* need state
* timing
* social energy
* opportunity window
* practical fit
* emotional framing
In practice, every recommendation should be frameable as one or more of:
* Act now
* Good fit nearby
* Best at this time
* Good for your current energy
* Worth saving for later
* Good for this practical need
* Special because of current conditions
* Worth detouring for
* Socially alive / active
* Quiet / restorative / easy
________________

10.4 ARCHITECTURAL POSITION
Moment Framing should run after Slot Ranking Engine.
Pipeline order:
1. Candidate generation
2. Relevance scoring
3. Opportunity scoring
4. Action Horizon assignment
5. Role assignment
6. Route evaluation
7. Sequence planning
8. Slot ranking
9. Moment framing
10. UI rendering
This is important because framing should reflect the actual selected reason for surfacing, not pre-rank guesses.

10.7.1 moment_primary_family
Purpose
The top-level explanation family.
This is the main bucket of “why this matters right now.”
Allowed values
IMMEDIATE_ACTION
SOCIAL_ENERGY
OPPORTUNITY
DISCOVERY
PLANNING_GUIDANCE
NEED_STATE
RECOVERY
TRANSITION
ANCHOR_REINFORCEMENT


You initially proposed 6 families — that’s good.
But in production, you should also add:
* RECOVERY → for cool-down, sit-down, low-friction reset moments
* TRANSITION → for “on the way”, “good next stop”, “fits between anchors”
* ANCHOR_REINFORCEMENT → for “this is why this anchor matters”
These will become very important in travel feeds.
Population logic
Choose the family with highest moment family score.
moment_primary_family = argmax(
    immediate_action_score,
    social_energy_score,
    opportunity_moment_score,
    discovery_moment_score,
    planning_guidance_score,
    need_state_score,
    recovery_score,
    transition_score,
    anchor_reinforcement_score
)

10.7.3 moment_primary_score
Purpose
Strength of the top moment explanation.
This is not overall item quality.
It is:
How strongly can this item be framed as this specific moment right now?
Range
0.0000 – 1.0000


Formula
Use weighted evidence aggregation:
moment_primary_score =
(
  contextual_fit * 0.30 +
  timing_fit * 0.20 +
  route_fit * 0.15 +
  need_fit * 0.15 +
  opportunity_fit * 0.10 +
  social_fit * 0.05 +
  confidence_support * 0.05
)


You can tune weights by family.
________________


10.7.4 moment_secondary_family
10.7.5 moment_secondary_type
10.7.6 moment_secondary_score
Purpose
Many items deserve two truths, not one.
Example:
* “Quick indoor break”
* “Good while the heat is high”
Or:
* “Worth a short detour”
* “Best before sunset”
This lets UI support:
* a primary label
* a supporting reason
* a richer explanation
Population logic
Take the next-best moment family/type if:
secondary_score >= 0.65
AND
secondary_score within 0.15 of primary_score
AND
secondary_type not semantically redundant


________________


10.7.7 moment_confidence
Purpose
How confident the system is that this framing is truthful and stable.
This prevents bad UX like:
* saying “lively right now” with no real evidence
* saying “great for sunset” at 2 PM
* saying “quick stop” for a 90-minute museum
Formula
moment_confidence =
(
  signal_coverage_score * 0.35 +
  signal_agreement_score * 0.35 +
  data_freshness_score * 0.20 +
  contradiction_penalty_adjusted * 0.10
)


Where:
A) signal_coverage_score
How many required signals exist?
signal_coverage_score = available_required_signals / total_required_signals


B) signal_agreement_score
Do upstream modules agree?
Example:
* Opportunity says yes
* Need-state says yes
* Route says yes
* Sequence says yes
Then confidence should rise.
C) data_freshness_score
Live inputs degrade over time.
D) contradiction_penalty_adjusted
If the framing conflicts with item reality, confidence drops.
Example:
* “quick stop” + dwell_time = 120 min
* “cool indoor break” + item is outdoor
* “best before sunset” + sunset value weak
________________


10.7.8 moment_urgency_level
Purpose
How much the moment should feel like:
* do this now
vs
* nice to know
Range
0–1


Formula
moment_urgency_level =
(
  closing_soon_score * 0.35 +
  time_window_decay_score * 0.30 +
  current_fit_vs_future_fit_delta * 0.20 +
  opportunity_expiry_score * 0.15
)


Example:
High urgency:
   * closes in 40 min
   * best only at golden hour
   * weather window temporary
Low urgency:
   * all-day indoor museum
   * always decent coffee shop
________________


10.7.9 moment_actionability_level
Purpose
How easy it is to act on this right now.
This is very important and underused.
A recommendation can be relevant but not actable.
Formula
moment_actionability_level =
(
  proximity_score * 0.30 +
  route_convenience_score * 0.25 +
  effort_score * 0.20 +
  open_now_score * 0.15 +
  friction_penalty_adjusted * 0.10
)


High examples:
   * 4 min away
   * on current route
   * no reservation needed
   * easy entry
Low examples:
   * 40 min away
   * uphill
   * ticketed
   * currently crowded
   * requires planning
________________


10.7.10 moment_social_intensity
Purpose
Measures whether this moment should be framed as:
   * lively
   * popular
   * energetic
   * social
   * atmospheric
Formula
moment_social_intensity =
(
  live_popularity_score * 0.40 +
  historical_daypart_crowd_score * 0.25 +
  nightlife_affinity_score * 0.15 +
  user_visible_activity_score * 0.10 +
  review_energy_language_score * 0.10
)


Use this only when confidence is strong enough.
If weak, suppress social framing entirely.
________________


10.7.11 moment_energy_fit_level
Purpose
How well the item matches the user’s current energy state.
Examples:
   * after long walking → low effort café / shaded stop scores high
   * evening social mode → bar / promenade / lively plaza scores high
   * museum fatigue → scenic open-air pause scores high
Formula
moment_energy_fit_level =
1 - ABS(item_energy_demand - user_current_energy_tolerance)


Normalized to 0–1.
________________


10.7.12 moment_need_fit_level
Purpose
How well this satisfies the likely practical need right now.
This is crucial for your Need-State Moments.
Possible inferred needs:
   * lunch
   * dinner
   * snack
   * coffee
   * cool down
   * restroom vicinity
   * sit-down
   * rain shelter
   * kid-friendly stop
   * low-energy stop
   * scenic break
Formula
moment_need_fit_level =
SUM(weighted need match signals)


More concretely:
moment_need_fit_level =
(
  explicit_need_match * 0.45 +
  inferred_need_match * 0.30 +
  daypart_need_match * 0.15 +
  context_need_match * 0.10
)


________________


10.7.13 moment_copy_variant_id
Purpose
Separates decision logic from surface wording.
Do not generate copy directly from raw scores.
Instead:
   * choose a structured moment type
   * then map it to copy variants
Example:
moment_primary_type = COOL_INDOOR_BREAK
moment_copy_variant_id = NEED_COOL_INDOOR_BREAK_V2


This lets you:
   * A/B test labels
   * localize later
   * keep consistent UX tone
   * avoid chaotic phrasing
________________

10.7.18 moment_suppress_flag
Purpose
Suppress weak or misleading moment framing.
Set to 1 when:
   * confidence too low
   * moment too generic
   * no strong situational explanation exists
   * chosen frame conflicts with item truth
Example:
Do not show:
   * “Good right now”
   * “Worth visiting”
   * “Popular stop”
unless it is genuinely grounded.
This field protects UX quality.
________________


10.7.19 moment_fallback_flag
Purpose
Used when no strong contextual frame exists, and the system falls back to a safer explanation like:
      * Nearby stop
      * Good area pick
      * Useful if you’re around here
Fallbacks are okay — but should be explicitly marked.

Now let’s define how each family is actually scored.
________________


10.8.1 IMMEDIATE ACTION SCORE
Meaning
Can this be framed as something easy and relevant to do now?
Formula
immediate_action_score =
(
  actionability_level * 0.35 +
  proximity_score * 0.20 +
  low_commitment_score * 0.15 +
  open_now_score * 0.15 +
  sequence_fit_score * 0.10 +
  route_fit_score * 0.05
)


Strong examples
      * 5-minute scenic overlook
      * quick café stop
      * small museum on current path
________________


10.8.2 SOCIAL ENERGY SCORE
Meaning
Is this moment socially active / lively / atmospheric now?
Formula
social_energy_score =
(
  social_intensity * 0.40 +
  evening_alignment_score * 0.20 +
  nightlife_affinity_score * 0.15 +
  popularity_now_score * 0.15 +
  visible_activity_score * 0.10
)


Only show if confidence is high.
________________


10.8.3 OPPORTUNITY MOMENT SCORE
Meaning
Is there a temporary reason this is especially good right now?
Formula
opportunity_moment_score =
(
  opportunity_engine_score * 0.40 +
  urgency_level * 0.20 +
  current_conditions_advantage * 0.20 +
  time_window_strength * 0.15 +
  rarity_of_window_score * 0.05
)


Examples:
      * before sunset
      * after heat drops
      * before close
      * low queue window
________________


10.8.4 DISCOVERY MOMENT SCORE
Meaning
Can this be framed as a rewarding, less-obvious find?
Formula
discovery_moment_score =
(
  low_discoverability_score * 0.30 +
  uniqueness_score * 0.20 +
  hidden_gem_score * 0.20 +
  detour_worthiness_score * 0.15 +
  localness_score * 0.10 +
  low_mass_tourism_penalty_adjusted * 0.05
)


Use carefully.
Do not call everything a hidden gem.
________________


10.8.5 PLANNING GUIDANCE SCORE
Meaning
Is the best framing not “do now” but “remember this smartly”?
Formula
planning_guidance_score =
(
  future_fit_score * 0.35 +
  current_actionability_penalty_adjusted * 0.20 +
  daypart_specificity_score * 0.20 +
  anchor_pairing_value * 0.15 +
  tomorrow_relevance_score * 0.10
)


________________


10.8.6 NEED STATE SCORE
Meaning
Does this satisfy a likely practical or physical need right now?
Formula
need_state_score =
(
  need_fit_level * 0.45 +
  current_daypart_need_alignment * 0.20 +
  recovery_support_score * 0.15 +
  actionability_level * 0.10 +
  environmental_relief_score * 0.10
)


This family should become one of your highest-value UX layers.
Because users often aren’t thinking:
“Which attraction should I do?”
They’re thinking:
“I need lunch / shade / a break / somewhere easy.”
________________


10.8.7 RECOVERY SCORE
Meaning
Good for slowing down, cooling off, sitting, or resetting.
Formula
recovery_score =
(
  low_effort_score * 0.30 +
  seated_restfulness_score * 0.20 +
  environmental_relief_score * 0.20 +
  energy_fit_level * 0.15 +
  route_ease_score * 0.10 +
  low_queue_score * 0.05
)


________________


10.8.8 TRANSITION SCORE
Meaning
This works because it fits between bigger things.
Formula
transition_score =
(
  route_continuity_score * 0.35 +

  low_detour_score * 0.20 +
  sequence_bridge_value * 0.10 +
  movement_convenience_score * 0.10

This is extremely useful in itinerary-style feeds.
________________


10.8.9 ANCHOR REINFORCEMENT SCORE
Meaning
This is a defining stop that reinforces why this area matters.
Formula
anchor_reinforcement_score =
(
  anchor_strength_score * 0.35 +
  area_signature_score * 0.25 +
  landmark_importance_score * 0.20 +
  must_do_score * 0.15 +
  trip_identity_value * 0.05
)

10.9 HOW TO DETERMINE moment_primary_type
This should not be a single formula.
It should be a rule + score hybrid.
That means:
      1. compute family scores
      2. compute type-specific scores inside each family
      3. apply eligibility rules
      4. choose the strongest valid type
This avoids nonsense like:
      * “Quick break stop” for a 2-hour palace
      * “Catch before it closes” for a place open until midnight
      * “Cool indoor break” for an open-air beach promenade
________________


10.10 TYPE ELIGIBILITY RULES (VERY IMPORTANT)
Before a moment type can even compete, it should pass hard truth checks.
________________


Example: COOL_INDOOR_BREAK
Eligibility
item_indoor = 1
AND heat_relief_score >= 0.60
AND dwell_time_minutes <= 90
AND seated_or_restful_score >= 0.40


________________


Example: BEST_BEFORE_SUNSET
Eligibility
sunset_value_score >= 0.70
AND minutes_to_sunset BETWEEN 20 AND 150
AND weather_visibility_score >= 0.50


________________


Example: CATCH_BEFORE_IT_CLOSES
Eligibility
minutes_to_close <= 90
AND open_now = 1
AND estimated_visit_possible = 1


________________


Example: QUICK_BITE_NEARBY
Eligibility
category IN ('restaurant','cafe','food_market','bakery')
AND distance_minutes <= 12
AND average_dwell_minutes <= 50
AND open_now = 1


________________


Example: WORTH_A_SHORT_RIDE
Eligibility
distance_minutes BETWEEN 10 AND 30
AND detour_worthiness_score >= 0.65
AND route_penalty <= 0.45


________________


Example: LIVELY_RIGHT_NOW
Eligibility
social_intensity >= 0.70
AND confidence >= 0.70
AND current_daypart IN ('late_afternoon','evening','night')


________________

10.16 SUPPRESSION RULES (CRITICAL FOR UX QUALITY)
This is where most systems fail.
Not every item should get a strong “moment.”
Suppress when:
moment_primary_score < 0.58
OR moment_confidence < 0.60
OR chosen type fails truth checks
OR label would feel generic
OR primary and secondary reason conflict


When suppressed:
      * show nothing
      * or show a neutral support label
Examples of neutral fallback:
      * Nearby option
      * Good area pick
      * Popular in this area
      * Easy stop around here
But keep fallback use low.
